# Controller

systems-intelligence 0.4 adds `framelm.controller` and a **Controller** browser tab.
The existing `framelm` imports, Chat, Context Studio, generator recipes and CLI
commands remain available. P&R is installed as the sibling `PandR_v3` package;
its implementation is not copied into FrameLM.

## Install and launch

Requires Python 3.11+ with SQLite FTS5. From this directory on Windows:

```powershell
.\build.ps1
.\start-context-studio.cmd
```

The build installs both local packages, tests both, and writes their wheels and
source distributions into a timestamped directory under `dist`. It uses the
existing P&R virtual environment when present, or creates `.venv` here. Override
with `-Python 'C:\Python314\python.exe'` when creating an environment, or
`-EnvironmentPath PATH` to choose an environment. `-Offline` uses only installed
dependencies/local packages; `-SkipTests` skips tests. No database is cleared.

On other platforms, or with an existing environment:

```sh
python -m pip install -e ../PandR_v3 -e .
python -m framelm --config configs/demo.json studio
```

The extractive backend requires no model server. PyTorch remains optional, via
`requirements-neural.txt`. P&R supplies SymPy, numerical plotting and Pillow.
For Ollama incremental output set `"stream_output": true` in the configuration.
The compatibility default is a complete-response chunk. Both modes identify
missing token detail; streaming chunks are not represented as tokens. The tiny
backend records generated bytes, and training records batches, steps and held-out
evaluations. These are observations, not hidden model reasoning.

## Browser workspace

Select **Controller**, or use **Inspect** beside a context and **Inspect chat in
Controller** beside a conversation. Select contexts and chats together; selecting
a chat includes all its stored turns. The selector and event list have Load more
controls. The state inspector, replay data and selected plots include every page.

Click an event or scrub the journal position to inspect historical state and the
selected event's correlation, causation, payload and outcome. Paste a correlation
ID into **Causal run** to inspect that entire run. Filters select their members at
the chosen historical position; event queries use membership at their end
position, so provisional activity preceding an entity's commit remains visible.
Saved filters store a selection definition, evaluated against historical state.

Choose bytes, revisions, context size, enabled state, generation counts, chat
activity, retrieval/candidate scores, latency or outcomes. Published custom views
appear as `view:NAME`. Every view declares source fields and units.

Use **Play replay**, **Export GIF + data**, or **Export data**. The defaults are
1000×700, five frames per second and a maximum of 500 frames. A long selection
requires an explicit frame stride; it is not silently truncated. Committed state
transitions are the default frames. Include lifecycle frames to see provisional
generation/output activity. Export JSON downloads the complete current selection.

The workbench exposes registered application commands and all P&R plan operations
through `pandr.commit`. The registry includes P&R's plan method signatures and
command names. For example:

```json
{"revision":0,"commands":[{"op":"set_function","function":"union(sin(x), abs(x), implicit(x**2+y**2-4))"}]}
```

Select `pandr.plot` to draw the current P&R function or enter a function explicitly:

```json
{"functions":"sin(x)","x_range":[-7,7],"y_range":[-2,2],"resolution":400}
```

The same plan interface provides composition, geometry/fabric, sequences,
contracts, alphabets, layers, scripts, media rendering and signal routing. Script
execution and signal delivery are separate commands with their own outcomes.
Use `pandr.inspect` to read the current revision before a commit. Arbitrary
Python callables remain available through the shared Python P&R plotting API.
Numerical plots do not expand the exact contact solver's certification limits.

## Python and CLI

```python
from framelm.core import load_config
from framelm.controller import get_controller
from pathlib import Path
from uuid import uuid4

with get_controller(load_config(Path('configs/demo.json'))) as controller:
    context = controller.dispatch('context.append', {
        'title': 'Unicode example Ω', 'body': 'Groups, symmetry, 数据 😀',
        'enabled': True, 'tags': 'mathematics'
    }, request_id=str(uuid4()))
    selected = {'ids': ['context:' + context['id']]}
    position = controller.inspect(selected)['at_sequence']
    state = controller.inspect(selected, at_sequence=position, include_models=True)
    events = controller.events(selected, after_sequence=0, limit=100)
    plot = controller.plot(selected, at_sequence=position, view='bytes')
    for frame in controller.replay(selected, 1, position):
        print(frame['at_sequence'], frame['total'])
    exported = controller.export_replay(selected, 1, position, format='gif')
```

`inspect` supports `offset` and `limit` (1–1000), and returns `next_offset`,
`at_sequence` and `publication_lag`. `events` returns `next_sequence`. Pin the
returned position while paging. Selections accept an ID, list of IDs, or objects
with `ids`, `kinds`, `query`, `enabled`, `tags`, `saved_filter` and `correlation`.
IDs use `kind:id`; ID patterns such as `context:*` are also supported.

```powershell
python -m framelm controller registry
python -m framelm controller inspect --data '{"selection":{"kinds":["context","chat","turn"]},"limit":100}'
python -m framelm controller dispatch --data '{"command":"pandr.plot","payload":{"functions":"sin(x)"},"request_id":"my-sine-plot"}'
```

Browser HTTP uses `/api/controller/{registry,inspect,events,plot,skills}` for
queries and `/api/controller/dispatch` for commands. Writes retain Studio's local
Host, Origin and CSRF checks. Machine clients should normally use Python/CLI.
The action console shows each command's schema, capability and revision rules.

## Persistence, recovery and branching

For an application database `state/contexts.sqlite3`, the journal lives at
`state/contexts-controller/journal.sqlite3`. Application mutations and their
`controller_outbox` records commit in the same SQLite transaction. A relay uses
P&R's kernel-owned file lock to publish them idempotently to the controller
journal. IDs deduplicate publication after a crash. Generator records are only
committed context state after the generator's database transaction succeeds.
Cancelled records and progress remain provisional journal observations.

The initial migration captures existing contexts, complete chats/turns and index
state, preserving original timestamps. It does not invent earlier events.
Entity versions are immutable state checkpoints; historical reads reconstruct
them without invoking handlers, models, scripts or external actions. Calling or
publishing an event is not an application command.

Command request IDs are bound to a payload fingerprint. A completed retry returns
its stored result. A running/indeterminate retry reconciles recorded evidence
without repeating the action. An application commit whose publication/result
was interrupted reports `committed_pending_result`. P&R commits reconcile against
P&R request receipts. External effects without definitive evidence remain
`indeterminate`; inspect them before issuing a new request. The workbench exposes
`controller.reconcile` with the original `request_id` and `command`.

`controller.branch(position, NEW_DIRECTORY)` reconstructs the whole workspace,
including contexts, chats/turns, index references, generator states, custom views,
saved filters, skill definitions and recorded P&R state/artifacts. It requires a
new destination and leaves the source unchanged. The new config is
`NEW_DIRECTORY/configs/controller.json`; the branch records its parent journal
and position. Skills are copied disabled and unapproved, without grants; autonomy
is paused. Historical proposals are retained, with unfinished proposals marked
inactive in the branch. Model servers and installed Python dependencies remain host resources.

## Recoverable mathematical model

`controller-byte-function/1` serializes a typed canonical state to UTF-8 bytes.
Types distinguish null, booleans, arbitrary integers, finite floats (hexadecimal,
including negative zero), text, bytes, tuples, lists and ordered dictionary entries.
This avoids collisions between user dictionaries and type markers. Unicode is
preserved without normalization. Non-finite numeric values are rejected.

For each byte `b[i]`, the exact function has value `b[i]` on `[i, i+1)`. Ordered
blocks hold at most 256 bytes using P&R's reversible byte codec, together with
offsets, lengths and SHA-256 hashes. The complete model also records byte length
and SHA-256. It is not expanded into an expression AST.

```python
from framelm.controller.models import encode, decode
assert decode(encode({'text':'数据 Ω😀','value':-0.0})) == {'text':'数据 Ω😀','value':-0.0}
```

Byte displays sample at most 4096 values per entity and declare the display
stride. Pixels and GIFs are numerical visualizations, not recoverable storage.
The companion ZIP contains complete selected events, timestamps, state/model
references, view definitions and per-file integrity hashes. GIF frame hashes,
order and durations are recorded too. Validate with:

```python
from framelm.controller.visuals import verify_bundle
verify_bundle('path/to/export.zip')
```

## Scripts, skills and plugins

See `examples/controller_plugin/plugin.json` and its Python entry point. Draft a
manifest in the browser, through `skill.draft`, or with
`controller.skills.draft('path/to/plugin.json')`. Dependencies are checked against
installed distributions; drafting never runs pip. Entry points must remain
inside the plugin package. The reviewed source is copied into the draft, so later
source-file edits do not silently change an approved version: redraft to use them.

Activation approves a specific digest covering executable source, schemas,
instructions, version and declarations. Any new draft invalidates activation and
grants, including pending proposals from the previous version. Approved scripts
run under P&R's managed subprocess service with cancellation, timeout, bounded
output and receipts. The runner supplies `controller` (the SDK client),
`input_data`, and records a script's `result` variable.

SDK `inspect`/`iter_entities` are restricted to the skill's declared entity scope.
`dispatch` requests actions through a loopback authenticated broker. By default,
the broker saves a proposal containing the exact command, targets, payload,
observed prior state, revisions and skill digest. The browser shows this content
before **Approve this action**. Revisions are revalidated by the service's
transaction when executing it. A stale proposal cannot overwrite a newer edit.

Grant autonomy for a particular approved digest, capabilities, entity scope and
budgets. Defaults: 30 seconds, 256 KiB output, ten action requests, eight causal
trigger levels. The default is supervised; drafting or activation alone grants
no autonomous application actions. Grants cannot exceed declared capabilities
or scope. Activation, new grants, approval and unpausing requested by a script
still require human review. Revoke or pause to prevent further automatic actions;
cancelled runs cannot undo actions already committed.

Subscriptions run asynchronously after event persistence, with delivery IDs,
deduplication, self-trigger prevention and causal depth limits. Only one
subscription service can hold the workspace's P&R file lock. Interrupted
deliveries become indeterminate instead of being blindly rerun. Inspection
inherits the skill's causal context and cannot retrigger that same skill.
`controller.skills.start()` runs subscriptions for a Python host; Studio starts
them automatically. `studio --no-browser` serves without opening a browser. No
OS startup service, unattended scheduler or remote publication is installed.

Plugins are trusted local Python with host-user access. Controller capabilities
govern actions mediated by the broker; they are not an OS security sandbox.
Do not activate code you do not trust. Namespace events as `plugin.PLUGIN.NAME`;
optional manifest `events` maps those names to JSON schemas. Each approved skill
registers a `plugin.PLUGIN.SKILL.run` command. Custom plots use SDK `publish_view`
and the `controller.view.publish` capability; their definition must contain
`source_fields`, `units` and numeric `series`.

## Validation

Run `build.ps1`, or both packages' `python -B -m unittest discover -s tests -v`.
Controller tests cover model round trips/corruption, full histories and large
groups, outbox interruption/duplicate publication, P&R receipt reconciliation,
concurrent chats, rollback, replay with execution disabled, branch references,
GIF decoding and bundle integrity, skill activation/version changes, supervision,
scope/grants, stale revisions, timeout/cancellation, budgets and deduplication.
Registry routing tests exercise every command through Python, CLI and HTTP using
probe handlers. A second registry-backed matrix runs every real command handler
through all three interfaces, including supervised and autonomous actions,
P&R scripts/export/replay, branches, cancellation requests and failure paths.
Training's missing-data/dependency failure is exercised without training a model.
Optional neural tests skip when PyTorch is not installed.

`tools/controller_preview.py` creates a separate `.controller-preview` fixture
for browser verification. It never opens the configured application database.
